# CME Internship & Training Portal — Django Edition

A Python/Django rebuild of the CME Internship & Training Portal. It does **not** use Node.js, React, npm, Supabase, or a hosted database. The default database is local SQLite; the UI uses Django templates, HTML, and CSS.

## Access policy — no public registration
- There is **no public sign-up or self-registration page or route**. `/register/` and `/signup/` are not configured.
- Only an authorised CME administrator creates accounts in the Django admin console and assigns each account a role/profile.
- Interns and team members sign in using credentials issued directly by CME. Passwords should be shared privately and changed after first sign-in.

## Included modules
- Premium responsive dark navy / electric blue / violet CME portal landing page and member sign-in
- Role-based workspace: Administrator, Founder, Intern Head, HR/Evaluator, Intern
- Internship & training program catalogue with admin-managed descriptions, eligibility, duration, dates, and status
- Task management with role-based permissions, intern submissions, review feedback, and controlled point awards
- Attendance records
- Announcements with audience targeting
- Certificate records and public verification page for issued certificates
- Django admin console for managing users, profiles, tasks, submissions, attendance, announcements and certificates
- Basic automated tests

## Requirements
- Python 3.10+
- pip

## Windows setup (PowerShell)
```powershell
cd CME_Training_Internship_Django
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```
Open `http://127.0.0.1:8000/` for the portal, `/programs/` for internship programs, and `http://127.0.0.1:8000/admin/` for administration.

## First-time setup
1. Create the initial administrator using `python manage.py createsuperuser`. This is an administrative setup step, not a public registration feature.
2. Sign in at `/admin/`.
3. Create intern/HR users under **Authentication and Authorization → Users**.
4. Create a **Profile** for each user and select the appropriate role. Intern IDs are generated when an Intern profile is saved. If an HR/evaluator account should use the Django admin console, enable **Staff status** on that user.
5. Create Founder and Intern Head accounts by creating a user and assigning the matching Profile role. These roles and the Administrator can create/edit tasks, set maximum task points, review intern submissions, and award points. HR/Evaluator accounts are view-only for published tasks. Interns can view their assigned/published tasks and submit work only; they cannot create tasks, change point values, review submissions, or award points. The Django admin console is restricted to superusers.
6. Interns sign in at `/login/` with the username/email and password created by the administrator. There is still no public self-registration route.

## Certificate verification
Create a Certificate record in Django admin and mark **Is issued** only after approval. Open `/verify/<certificate-code>/` to show its verification page. Codes are generated by the model and are not government-issued credentials.

## Security and production notes
- Public self-registration is disabled; account creation is admin-managed.
- Change `DJANGO_SECRET_KEY`, set `DJANGO_DEBUG=False`, and configure `DJANGO_ALLOWED_HOSTS` before deployment.
- SQLite is suitable for local development and small pilots. A production deployment should use a managed database, HTTPS, backups, and a configured email provider if email notifications/OTP are required.
- This starter includes no fake user records or demo credentials. Charts and dashboard counts use actual database records.
- Email OTP, file uploads, payment processing, PDF certificate rendering and automatic certificate eligibility are not implemented in this build; certificate records and code verification are implemented.

## Core Team workspace

The connected Core Team workspace is available at `/core-team/`. Core Team accounts must be created by an authorized CME administrator (there is no public sign-up): create a user in Django Admin, then create/update their Profile with role `Core Team`. The account's first login uses the username/email and password issued by CME. Run `python manage.py migrate` after updating the project.
